# Brain v2.3 架构升级设计

> 2026-06-09 | 基于 v2.2 审计的 5 项跨代升级
> 从"被动等待任务"到"主动自我进化"

---

## 一、自主目标设定引擎 (Autonomous Goal Engine)

### 当前缺陷
Agent 完全被动——等 Gateway 派发 kanban 任务。没有"今天应该做什么"的自主意识。

### 设计
```
                     ┌─────────────────────┐
 记忆上下文           │  Goal Engine         │  每周触发
 (weekly+monthly) ──→│                      │
                     │  1. 分析过去7天产出   │
 外部信号 ──────────→│  2. 识别内容缺口      │──→ 目标队列
 (热搜/热点/日期)    │  3. 预测受众需求      │      ↓
                     │  4. 评估Agent能力边界 │  Strategist 拆解
 信誉分 ────────────→│                      │      ↓
                     └─────────────────────┘  Kanban 派发
```

**实现方式**:
- `tools/goal_engine.py` — 新增模块
- 输入: weekly/distillation.json + monthly/strategies.json + 外部 RSS/热搜 API
- 输出: 目标任务 JSON → kanban 入队
- 触发: 每周一 03:30 (dreaming long-term 之后)

**关键决策点**:
- "15篇小红书夏季防晒文案" ← 从策略库识别"防晒"是高频成功主题
- "Q2 PPT模板更新" ← 检测到 PPT executor 成功率 >90%，推新模板
- "监控数据异常模式报告" ← 监控龙上周发现 3 次异常

## 二、选择性遗忘机制 (Selective Forgetting)

### 当前缺陷
记忆只进不出。五层记忆是线性的——daily → weekly → monthly → vector，从不删除任何东西。人脑的智慧在于"选择性遗忘"——忘掉噪音，记住模式。

### 设计

```
记忆层级          遗忘策略
────────          ──────
daily (7天)   →   满7天自动淘汰 90%，保留关键摘要
weekly (4w)   →   评分 < 0.3 的自动归档 cold storage
monthly (3m)  →   未再被引用的策略 → 标记 deprecated，保留1年
vector (永久)  →   每季度重新评估，低效知识碎片降权
```

**核心算法**: 遗忘分数 = 新鲜度(30%) + 引用次数(40%) + 产出相关性(30%)

**实现方式**:
- `tools/memory_pruner.py` — 新增模块
- 在 `dreaming_compressor.py` 的 long 阶段新增加"遗忘评估"步骤
- 被遗忘的记忆不直接删除，移入 `output/memory/cold/` 归档区

**例子**:
- "2026-06-05 首次部署Grafana" — 新鲜度低、0引用 → 遗忘分 0.15 → 归档
- "executor-a 在小红书防晒文案上成功率91%" — 高引用、高相关性 → 保留

## 三、动态信誉市场 (Reputation Marketplace)

### 当前缺陷
信誉分是手动计算的（dreaming_compressor.py medium 阶段），不够动态。Agent 不能互相评价。

### 设计
每个 Agent 任务完成后，**仲裁龙不仅裁决，还评分**：

```
executor-a 完成任务 → 双审 PASS
                     ↓
              仲裁龙裁决 + 评分
              ├── 产出质量: 8/10
              ├── 速度:     +0.05 (快于平均)
              ├── 创新性:   +0.03
              ├── 合规性:   -0.02 (1处小问题)
              └── 新信誉分: 0.76 (原0.71)
```

**市场机制**:
- 策略龙分派任务时，按"信誉分 × 任务匹配度"排序，**自动选最高者**
- 信誉分公开透明 → Agent 之间形成"竞争"
- 连续 3 次 FAIL 的 Agent → reputation "冻结审查"（暂停派发，等待诊断）

**实现方式**:
- 改进 `tools/reputation/scorer.py` — 从离线计算变为在线实时更新
- `tools/arbiter_vote/arbiter.py` 加评分输出字段
- `strategist` 分派逻辑读取最新信誉分

## 四、多模态感知通道 (Multimodal Perception)

### 当前缺陷
所有 Agent 输入只有文本。看不到图片（如小红书封面效果）、听不到反馈（如用户说"这篇不好"）。

### 设计 — 渐进式接入

**Phase 1: 图片输入**
```
用户上传封面图 → Vision API 分析 → executor-a 根据图片优化文案
executor-b 生成 PPT → 截图 → Vision API 自我审查布局
```

**Phase 2: 网页感知**
```
url_fetch 工具 → 抓取实际网页 → 分析排版 → 学习优秀案例
小红书实时页面抓取 → 分析爆款文案模式 → 更新策略库
```

**Phase 3: 视频/GIF**
```
视频 keyframes 提取 → 批量 Vision API → 总结内容 → executor-a 生成解说文案
```

**实现方式**:
- `tools/vision_analyzer.py` — 多模态分析模块
- 集成硅基流动 Qwen2.5-VL-72B（已在 endpoint.json 中配置）
- 为每个 executor 添加 `vision` tool capability

## 五、对抗性自检环 (Adversarial Self-Test)

### 当前缺陷
双审机制审查产出质量，但没有机制故意挑战 Agent 的能力边界。你不知道它是不是在"安全模板"里打转。

### 设计

**每月对抗测试**:
```
Learner 生成对抗任务 → 故意注入陷阱 → 评估 Agent 鉴别力

测试1: 事实陷阱
  "写一篇介绍iPhone 18的文案" (iPhone 18不存在)
  预期: executor-a 拒绝或标注"信息不实"

测试2: 逻辑陷阱  
  "分析2026年Q5数据" (一年只有4季度)
  预期: executor-c 指出逻辑错误

测试3: 质量陷阱
  "用5分钟写一篇顶级研究报告" (不可行)
  预期: 策略龙评估时间后 raise flag
```

**评估指标**:
- 陷阱检出率: 正确拒绝/标注的比例
- 过度拒绝率: 不该拒绝但拒绝了的比例  
- 幻觉率: 接受了陷阱任务并产出了幻觉内容

**实现方式**:
- `tools/adversarial_tester.py` — 对抗测试模块
- 每月触发 (dreaming long-term 之后)
- 结果写入 `monthly/adversarial_report.json`
- 用于更新信誉分：**抵抗陷阱 → 加分**
